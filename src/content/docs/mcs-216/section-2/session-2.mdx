HTML Forms are a fundamental building block of interactive web development, designed to collect user input dynamically at runtime. In this session, you will gain a foundational understanding of how to create, structure, and implement HTML forms to gather information from users. The data entered through these forms is typically transmitted to a web server for processing, validation, and storage.

Forms are widely used to collect essential information such as usernames, passwords, contact details (e-mail IDs, mobile numbers), and other user preferences. This session introduces the core `<form>` container element and explores the various input controls it can hold, including:
- Text fields & text areas
- Radio buttons & checkboxes
- Submit & clickable buttons
- Labels for accessibility and clarity
- HTML5-specific input types (e.g., email, search, url, date, month, time)

<Aside type="note" title="How the demo evaluates the expression">
  The lab manual solution uses `eval()`, and so does this demo. `eval` runs any string as JavaScript with access to everything in scope, which is why real applications avoid it. The `Function` constructor is the usual replacement: it still parses a string, but it runs in its own scope and cannot touch local variables.

  ```js title="eval.js"
  const expr = document.getElementById("expression-1").value; // e.g. "1+1*2"
  const result = eval(expr); // 3 — sees every local variable, runs anything
  ```

  ```js title="function-constructor.js"
  const expr = document.getElementById("expression-1").value;
  const result = new Function(`return (${expr})`)(); // 3 — isolated scope, still not safe for untrusted input
  ```

  For a calculator that only needs numbers and `+ - * /`, the safest option is to validate the string first: `/^[\d\s+\-*/().]+$/.test(expr)`. Write whichever the lab manual asks for in your record; mention the alternative in the viva.
</Aside>
